# Demo 录制卡（90 秒 / 30 秒两版）

> 录屏是最省事的"作品集"。这套分镜的目的不是展示功能多，而是**按 Agent 岗的四项核心要求逐层递进**：
> 能跑 → 可控 → 可观测 → 可验证。
>
> 全程不需要联网、不需要 API Key（规则引擎模式即可跑完整链路）。

---

## 一、录制前准备

| 项 | 要求 |
|---|---|
| 应用 | 桌面图标启动（已安装版，非 dev 模式） |
| 账号 | 用一个干净的演示账号，别用真实简历 |
| 数据 | 建议先用示例档案（首次启动的 "FIRST RUN" 引导里有「选一份示例档案直接进炉」） |
| 窗口 | 最大化，或固定 1440×900（避免录出来太小看不清） |
| 屏幕 | 1080p 以上，缩放 100%（缩放会影响录屏清晰度） |
| 工具 | Windows：`Win + G`（Xbox Game Bar）或 OBS；macOS：`Cmd + Shift + 5` |
| 时长 | 90 秒版录 1 分 40 秒留余量，后期裁到 90 秒内 |

**录制前先跑一遍**：确认 Agent 能正常出步骤、编程题能判出 AC。录屏最怕中途卡住。

## 二、90 秒版分镜（主推）

### 第 1 段 · 0–15s｜Agent 在跑，而且看得见每一步

| 操作 | 画面 | 口播 |
|---|---|---|
| 简历页 → 点右侧「Agent 深度优化」→ 选「流程」或「agentic」模式 → 点运行 | 步骤条依次点亮：`analyze_jd → audit_text → rewrite_bullets → validate_rewrites → submit_result`，每步带耗时 | "这是一个可控的 Agent：每一步做什么、花多久，界面上直接能看到。" |

**要点**：让观众看到 **5 个工具名依次出现**，这是"工具调用"最直观的证据。

### 第 2 段 · 15–35s｜中途取消，已完成的改写不白跑

| 操作 | 画面 | 口播 |
|---|---|---|
| 运行中点「取消这次运行」 | 状态变 `CANCELLED`；**已经通过校验的改写仍在列表里**，未处理的条目标注"未处理" | "取消是在工具之间退出的，不是把整次运行炸掉——已经改好的部分保留，用户不用重来。" |

**要点**：这是与"套壳 demo"最明显的区别。**一定要拍**。

### 第 3 段 · 35–50s｜运行记录：能复盘，而且脱敏

| 操作 | 画面 | 口播 |
|---|---|---|
| 右上角「关于」→ 最近运行记录 → 点开刚才那次 | 表格：`tool / 输入摘要 / 输出摘要 / latencyMs / retryCount / tokens / errorType`；摘要显示成 `{len: 23, digest: a1b2…}` 而不是原文 | "落盘记录里没有简历正文——超过 12 字的字符串一律换成长度和摘要，但它仍然能用来复盘每一步。" |

**要点**：**摘要显示 `{len, digest}` 而不是原文**，这是隐私意识的直接证明。

### 第 4 段 · 50–70s｜编程题：C++ 判题，用例级对比

| 操作 | 画面 | 口播 |
|---|---|---|
| 左侧「05 笔试中心」→ 编程题 → 语言切 **C++ 17** → 故意写一个错答案 → 点「提交判题」 | 判题结果 `WA`，逐用例展开：`#2 输入 … 期望 … 实际 …`，带耗时 | "43 道题、三种语言，编译一次多用例复用；错了会逐条告诉你是哪个用例、期望什么、实际输出什么。" |
| 改对 → 再提交 | `AC`，通过 5/5，提交记录区出现一条绿色记录 | "过了就进提交记录，侧栏打勾。" |

**要点**：**故意先错一次**。只拍 AC 像演的，先 WA 再 AC 才有说服力。

### 第 5 段 · 70–90s｜终端：65 个用例、门禁全绿

| 操作 | 画面 | 口播 |
|---|---|---|
| 终端执行 `node evals/agent-bench.js` | 输出：任务数 65 / 行为符合预期 100% / 业务完成率 63.1% / 干净路径 100% / 编造技能率 0% / "✅ 全部达标" | "这些都是可复现的：65 个用例 9 类场景，包括往 JD 里塞指令诱导它编造技能的注入用例。" |

**要点**：终端输出**必须是真的跑出来的**，数字与 README 一致。

## 四、常见翻车与备选

| 情况 | 处理 |
|---|---|
| Agent 跑不出步骤（模型未配置） | 切到**规则模式**（零配置），步骤条同样会出现，只是没有 `llm_rewrite` 这一步 |
| 编程题判题很慢（首次编译） | 第一次跑 C++ 会有 1–2s 编译 + Defender 扫描，**录之前先跑一次预热** |
| 运行记录是空的 | 先跑一次 Agent，记录才会写入；记录按账号分文件，换账号会看不到 |
| 窗口太小看不清 | 只录 1280 宽也行，但要把浏览器/终端字号调到 14px 以上 |
| 录出来 200MB+ | 用 HandBrake / ffmpeg 压到 10MB 内（`-crf 28`），或直接转 GIF（≤8MB 才好发） |

**压缩命令**（有 ffmpeg 的话）：
```bash
ffmpeg -i demo-raw.mp4 -vf "scale=1280:-2" -c:v libx264 -crf 28 -an demo.mp4
```

### 截图脚本的两个坑（已修，记下来免得再踩）

1. `npm run smoke:ui` 必须在**剥掉 `ELECTRON_RUN_AS_NODE`** 的环境下跑，
   否则 electron 会退化成 Node，报 `Cannot read properties of undefined (reading 'whenReady')`：
   ```bash
   env -u ELECTRON_RUN_AS_NODE npm run smoke:ui
   ```
2. mock 的 exam handler 曾把「第一个入参」当 userId 用（真实主进程是从 session 取的），
   导致组卷时抛「用户不存在」。已加 `hU()` 包装，把当前登录的演示用户 id 注入进去。
