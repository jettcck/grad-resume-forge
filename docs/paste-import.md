# 粘贴导入（从招聘网站把岗位信息带进来）

> 场景：在 BOSS 直聘 / 智联 / 前程无忧上看到合适的岗位，不想一个个手敲公司名、岗位、城市、薪资。

## 一、为什么是「粘贴」而不是「抓取」

这是一个刻意的选择，不是能力不足：

1. **会连累用户自己的账号。** BOSS 直聘这类平台有请求签名（`__zp_stoken__`）、滑块、设备指纹。
   要稳定抓到数据，只能去**绕过技术保护措施**；一旦被判定为爬虫，用户正在用的求职账号
   （含已投记录、与 HR 的沟通记录）可能被封。**这个应用存在的意义是保住用户的投递数据，
   不该反过来把它置于风险里。**
2. **法律风险不是「差不多」。** 《反不正当竞争法》有明确判例（大众点评、淘宝、智联等爬虫案）；
   绕过技术措施还可能触及《刑法》第 285 条；岗位信息常含 HR 联系方式，批量采集落入《个人信息保护法》。
3. **技术上必然短命。** 反爬一升级就废，用户看到的是「某个平台又失败了」。

**所以本功能的动作全部发生在用户自己的机器上**：用户在浏览器里看到岗位 → 复制 → 粘贴进应用 →
应用在本机解析。全程**不联网、不发任何请求到招聘平台**。

## 二、怎么用

投递管理 → 工具栏「粘贴导入」→ 粘贴 → 确认预览 → 导入。

解析出来的「公司所在地」会直接喂给[投递地点与距离](map-distance.md)：填了「北京·朝阳区」，
马上就能看到它离学校多远。

## 三、能识别什么

| 字段 | 识别方式 | 例子 |
|---|---|---|
| 链接 / 平台 | 域名映射（BOSS直聘 / 智联 / 前程无忧 / 猎聘 / 实习僧 / 拉勾 / 牛客 / 应届生 / 国聘 / 中国公共招聘网） | `zhipin.com` → BOSS直聘 |
| 薪资 | 覆盖 `15-25K`、`15-25K·14薪`、`1.5-2.5万`、`200-300元/天`、`20-30万/年`、`面议` | `15-25K·14薪` |
| 城市 · 区 | 复用距离功能的城市表（344 城市 + 2966 区县），并归一化 | `北京·朝阳区` → 北京朝阳 |
| 公司名 | 显式前缀（`公司：`）→ 公司后缀词表（有限公司/集团/银行/事务所…） | `某某科技有限公司` |
| 岗位名 | 显式前缀（`岗位：`）→ 岗位关键词词表 → 薪资行的上一行 | `Java开发工程师` |
| 学历 / 经验 | 学历与经验词表 | `本科及以上`、`3-5年` |
| 分享文本 | `【岗位_城市-区_薪资】公司 - 平台` 这种分享格式单独解析 | 见语料样例 |

支持的粘贴形态：
- **列表卡片**：`岗位名 / 薪资 / 城市·区 / 经验 / 学历`
- **详情页整页**：混杂「职位描述」「任职要求」等大段正文，不会把正文当成岗位名
- **分享文案**：`【…】公司 - 平台` + 下一行链接
- **批量**：用空行隔开多条，或每条各带自己的链接（字段不会串到别的记录上）
- **字段前缀**：`岗位：` / `公司：` / `工作地点：` / `薪资：`
- **实习岗**：`200-300元/天`

## 四、诚实性保证（这是重点）

1. **不编造。** 认不出就返回空并提示，绝不把无关文本当成岗位名。
   > 测试里有这条：`你好，这是一段普通文字` → 0 条候选 + 「没认出」提示。
   > 这条规则是解析器的一个约束：首行兜底当岗位名时，**必须还有别的识别信号**
   > （薪资/地点/公司/链接）才成立；否则纯聊天文字也会被"编"成岗位。
2. **每个字段标注来源**：`原文`（显式写的）/ `识别`（词表判断）/ `推断`（猜的），
   界面上用不同颜色区分，用户一眼能看出哪些需要核对。
3. **不静默写入**：导入必须经过「预览 + 逐条勾选 + 可编辑」，可以取消整批。
4. **不丢信息**：识别到的薪资/平台/学历/经验会写进投递记录的备注，不因为界面上没这几个输入框就丢掉。
5. **去重**：同公司 + 同岗位视为同一条，走更新而不是新增（避免批量粘贴产生重复记录）。

## 五、测试

| 测试 | 条数 | 守什么 |
|---|---|---|
| `test-job-import.js` | 50 | 用各平台真实排版当语料：BOSS 卡片 / BOSS 详情页 / 智联「万」薪 / 分享格式 / 实习僧「元/天」/ 批量不串位 / 显式前缀优先 / 公司名含城市名不被当地点 / **无关文本不产出候选** / 平台域名映射 |
| `scripts/screenshot.js` | +10 | 真实窗口点一次「粘贴导入」→ 弹框 → 注入样例 → 识别 1 条 → 预览四个字段都填好 → 点导入 → **投递卡片真的增加**（6→7） |
| `scripts/check-installed-asar.js` | +5 | 解析器、词表、预览勾选、域名映射、按钮接线都进了安装包 |

> 顺带说一个测试抓到的真问题：最初「看到链接就切块」的启发式，会把最常见的
> 「分享文案 + 下一行链接」拆成两块，链接落进没有岗位信息的第二块被丢掉 ——
> 结果平台名和链接全丢。现在只在**确实存在 2 个以上链接**时才按链接切块。

## 六、已知限制

- **只做本机解析，不替你去平台上取数**。公司名/岗位名仍需你复制一次。
  想要"自动同步"就得抓取，理由见第一节。
- **解析是启发式的**，所以一定有认不出的排版。界面把不确定的字段标出来并允许改，
  而不是假装 100% 准确。遇到认不出的排版，把原文发出来就能补规则。
- **不解析岗位描述正文**。JD 正文只用来避开误判，不进投递记录（避免把大段文字写进备注）。
- **公开/官方源（人社部公共招聘网、国聘、高校就业网）暂未接入**：这些要逐个核对使用条款后
  才谈得上接入，属于单独的一轮工作。
