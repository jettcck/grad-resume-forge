# 招聘平台投递同步（自动抓取 → 预览 → 增量合并）

> 场景：用户在 BOSS / 智联 / 前程无忧 / 实习僧 / 猎聘 / 拉勾 / 国聘 / 中华英才网投过简历，
> 想把「已投递 / 收藏」的记录带进应用统一跟踪。

## 一、动作链（用户视角）

投递管理 →「从平台同步」→ 选平台点「抓取投递记录 / 抓取收藏」：

```
点抓取
  → 后台打开同步窗口（不抢焦点），加载平台首页
  → 已登录？否 → 窗口交给你登录，登上自动继续（最多等 120 秒）
  → 自动走到「投递记录 / 收藏」页（已知路由直达 → 首页菜单 DOM 发现）
  → 页面自己的数据响应被持续累积（preload 钩子，只读旁路）
  → 预览弹窗：可勾选、可改字段，「已存在 · 将更新」直接标出
  → 导入：同平台同 ID / 公司+岗位相同的记录走更新，其余新增
```

全程只读：不逆向签名、不伪造请求、不向平台提交任何写操作；登录态只按平台存在本机独立分区。

## 二、进度可见（v1.12.22）

自动抓取动辄几十秒到两分钟（等登录最长 120 秒）。旧实现只有一个「正在抓取…」toast，
之后按钮一直转圈，用户完全不知道卡在哪。现在：

- 主进程每换一个阶段（`正在打开首页…` / `正在查找入口…` / `等待登录…` / `已抓到数据`）
  就通过 `jobsync:progress` 推给应用窗口；
- 同步面板顶部有进度行，实时显示当前阶段 + 已捕获的数据响应数；
- 抓取期间面板内所有按钮禁用（连点会并发跑两个 autoCollect，共享同一会话缓冲，结果不可预期）。

## 三、增量合并的铁律（v1.12.22 修复的数据丢失 bug）

旧实现在二次同步时把 patch 无条件写 `stage / place / url / notes`：

- 用户在手盘上把记录推进到「面试中」，一次再同步被打回「已投递」；
- 平台这次没返回地点，用户手填的「北京·海淀区」被空值清空；
- 用户自己写的备注被同步备注覆盖。

现在（主进程 `applications:importAuthorized` 与渲染层粘贴导入一致）：

| 字段 | 更新时的规则 |
|---|---|
| `stage` | **只进不退**：保留用户已有的阶段，不用同步值覆盖 |
| `place` / `url` / `address` / `notes` | 新值优先；**新值为空时保留用户已填内容** |
| `company` / `position` | 同步值（这是记录的身份） |

预览弹窗会把「已存在 · 将更新」的记录打上标签，标题标注「其中 N 条将更新已有记录」——
合并行为在导入前就是可见的，不靠猜。

## 四、自检修掉的其余问题（v1.12.22）

1. **页面体检曾无超时**：平台页面主框架导航挂起时 `executeJavaScript` 永不 resolve，
   `looksLikeLoginWall` / `status` 一起卡死，「抓取」按钮永久转圈。现在体检带 2.5 秒超时，
   超时保留上一次的结果，不误报「空白页」。
2. **空白页兜底定时器误伤**：打开窗口后 2.5 秒内的兜底检查可能在抓取途中触发，
   把平台视图卸掉、往用户面前闪一个诊断页。现在抓取中（`collecting`）定时器一律让路，
   每次新导航也会作废残留定时器。
3. **候选页重复尝试**：DOM 发现阶段会把 Step 3 已失败过的直达页重跑一遍，
   BOSS 每条候选要等满 12 秒——白等二十几秒。现在候选 URL 跨步骤去重。
4. **投递时间时区**：时间归一化曾用 `toISOString()`（UTC），东八区早上 7 点前的投递
   被算成前一天，用户看到「投递时间：昨天」以为数据错了。现在按本地日期归一化。

## 五、验证

- `npm test`：契约 / 同步 / 预览 / 粘贴导入等全套单测（含上述每条修复的回归钉）。
- `npm run smoke:ipc`：真实主进程 IPC 冒烟，含「授权导入增量合并」7 项实测。
- `npm run diag:delivery`：CDP 驱动真实应用，端到端验证进度通道、busy 守卫、
  预览标记与导入合并（20 项断言）。
